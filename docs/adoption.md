# 里親募集の仕様

アプリの「里親募集」のタブは、[ニャン友ねっとわーく北海道](https://nyantomo.jp/) の里親募集の一覧を、写真、名前、年齢、性別、状態 (里親募集中など) のカードで並べます。カードを押すと、サイトの詳しいページを、ブラウザで開きます。

この文書は、一覧をいつ、どれだけ取得して、どう保存し、どう更新するかの決まりです。動きを変えたら、この文書も直します。

## 取得元

- 一覧: `https://nyantomo.jp/satooya/` (一覧の固定ページに転送されます)。
- サイトは WordPress (Elementor と JetEngine) です。里親募集は REST API に出ていないので、ページの HTML を解析します (`core` の `parseAdoptionPage`)。
- 1 ページに 15 匹で、18 ページ (263 匹) ほどあります (2026-10-17)。
- 次のページは、一覧の固定ページ (ページの `canonical` の URL) に `?jsf=jet-engine&pagenum=N` を付けた URL です。`/satooya/` に付けると、転送されずに、空の一覧になります。
- 全ての猫の数は、1 ページ目の中のスクリプトにある `"found_posts":263` から読みます (進み具合の表示に使います)。
- サイトは、新しい猫を、一覧の先頭に並べます (並び順の決まりは、確かめていません。見た限りです)。
- 猫は、詳しいページの URL で見分けます。名前や写真が変わっても、URL が同じなら、同じ猫です。

## 保存

- 猫の一覧は、アプリのデータのフォルダ (`filesDir`) の `adoption-cats.json` に、JSON で保存します (`CatStore`)。
  - キャッシュのフォルダは、端末の空きが少ないと、システムに消されるので、使いません。
  - ページの HTML は、保存しません。新しい猫が入ると、ページの区切りがずれるためです。
  - 書きかけで止まっても、前の一覧が残るように、別のファイルに書いてから、置き換えます。
- 写真は、キャッシュのフォルダの `adoption-images` に、1 枚ずつ保存します (`ImageLoader`)。一度取得した写真は、通信しません。
- 保存した一覧と写真は、古くなっても、自動では消しません。消すのは、設定の「保存したデータを削除」だけです (下の「削除」)。

## 表示と取得のタイミング

| とき | 表示 | サイトから取得するもの |
|:---|:---|:---|
| 起動してから、初めて里親募集のタブを開いたとき (保存した一覧がある) | 保存した一覧を、すぐに表示する。新しい猫がいれば、追加するかをダイアログで聞く | 新しい猫を探す (下の「新しい猫の探し方」。普段は 1 ページ) |
| 起動してから、初めて里親募集のタブを開いたとき (保存した一覧がない) | 取得したページから、順に足していく | 全てのページ (下の「全てのページの取得」) |
| 2 回目からタブを開いたとき | 表示している一覧のまま | 取得しない |
| 更新 (更新のボタンか、一覧を引き下げる) | 表示している一覧のまま。新しい猫がいれば、先頭に足す | 新しい猫を探す。一覧が空のとき (最初の取得に失敗したときなど) だけ、全てのページ |
| 設定で、保存したデータを削除したとき | 一覧を空にする | 里親募集のタブを表示していれば、すぐに全てのページ。そうでなければ、次にタブを開いたときに |

## 新しい猫の探し方

起動後の最初の表示と、更新で使います (`AdoptionScreen.addNew`)。

1. サイトの 1 ページ目を取得します。
2. 表示している一覧にない猫 (URL で比べる。`core` の `newAdoptionCats`) を、新しい猫とします。
3. 新しい猫がいたページは、次のページも取得して、2 を繰り返します。新しい猫が 1 匹もいないページか、最後のページで止めます。サイトは新しい猫を先頭に並べるので、普段は 1 ページで止まります。
4. 起動後の最初の表示では、足す前に、ダイアログで「新しく里親を募集している猫が N 匹います。一覧に追加しますか？」と聞きます。
   - 「追加する」: 5 に進みます。
   - 「あとで」(または、ダイアログの外を押す、戻る): 足しません。次の更新で、また見つかります。
   - 更新 (ボタンと、引き下げ) では、聞かずに 5 に進みます (自分で更新を頼んだので)。
5. 新しい猫を、サイトの順のまま、一覧の先頭に足して、保存します。「新しい猫を N 匹、先頭に追加しました。」と表示します。
6. 新しい猫がいなかったときは、更新では「新しい猫はいませんでした。」と表示します (起動後の最初の表示では、何も表示しません)。

探している間の表示は、次のとおりです。

- 起動後の最初の表示: 何も出しません (保存した一覧を表示しているので)。
- 更新: 一覧の上に、引き下げの丸を回します。

## 全てのページの取得

保存した一覧がないときと、一覧が空のときの更新と、設定で削除したあとに使います (`AdoptionScreen.loadAll`)。

- 1 ページ目から最後のページまで、1 ページずつ順に取得します (同時には取得しません)。
- 取得したページの猫を、一覧の後ろに足していきます。取得している間も、一覧を見られます。ページの間で同じ猫が重なったら、足しません。
- 進み具合は、「120 / 263 匹」のような数と、上の横棒で表示します。全ての猫の数が分からなければ、横棒は動き続ける表示にします。
- 最後まで取得したら、一覧を保存します。

## 失敗したとき

- 取得に失敗したら、そこで止めて、エラーのメッセージを表示します。続きは、更新で、やり直します。
- 全てのページの取得の途中で失敗したときは、保存した一覧は前のままです (途中までの一覧は、保存しません)。
- 新しい猫を探している途中で失敗したときは、表示している一覧は、そのままです。
- 一覧の部品 (`.jet-listing-grid__items`) が見つからなければ、サイトの作りが変わったとみなして、エラーにします (`AdoptionParseException`)。そのときは、`core` の `parseAdoptionPage` を直します。

## 更新の操作

- 見出しの右の、更新のボタン (回る矢印のアイコン) を押します。
- 一覧のいちばん上で、一覧を下に引き下げます。
- 取得している間は、更新のボタンを押せません。引き下げても、何もしません。

## 削除

- 左から引き出すメニューの「設定」で、保存したデータ (一覧の JSON と、写真) の容量を確かめて、「保存したデータを削除」で消せます。消す前に、確認を出します。
- 消したあとは、表示している一覧と、メモリに残した写真も捨てて、上の表のとおりに、全てのページを取得し直します。

## お気に入り

- 里親募集のカードの右上の、ハートのボタンを押すと、お気に入りに入ります。もう一度押すと、外れます。
- 下のタブの「お気に入り」に、お気に入りの猫を、新しく入れた順に、同じカードで並べます。ここでハートを押すと、外れます。
- お気に入りは、アプリのデータのフォルダの `adoption-favorites.json` に保存します (`Favorites`)。猫の情報 (名前、写真の URL など) ごと保存するので、里親募集の一覧から消えても、残ります。
- 設定の「保存したデータを削除」では、お気に入りは消しません (写真は消すので、次に表示したときに、サイトから取得し直します)。
- お気に入りの名前や写真は、取得し直しません。お気に入りに入れたときのままです。
- 起動してから初めて「お気に入り」のタブを開いたときに、お気に入りの猫ごとに、サイトの詳しいページを 1 匹ずつ取得して、まだ里親を募集しているかを確かめます (`Favorites.checkOnce`)。
  - 詳しいページがない (404、410) か、ページの状態が「里親募集中」で始まらなければ (`core` の `isAdoptionOpen`)、募集が終わった (譲渡済み) とします。
  - 募集が終わった猫のカードは、写真と文字を灰色にして、状態の印を「譲渡済み」にします (里親募集の一覧に残っていれば、そちらも同じです)。
  - 通信に失敗した猫は、前の結果のままです。結果は、`adoption-favorites-closed.json` に保存するので、通信できないときも、灰色のままです。
  - 募集が再開したら (詳しいページが「里親募集中」に戻ったら)、灰色を戻します。
  - サイトに、譲渡済みの猫の一覧はありません。今の一覧の猫は、全て「里親募集中」なので、譲渡が決まった猫は、一覧から外れるか、ページがなくなると見ています (確かめたのは、ないページが 404 を返すことと、詳しいページの状態の書き方です)。

## まだ反映しないもの

- 里親が決まった猫を、一覧から消すこと。
- 状態 (里親募集中、トライアル中など) や、名前、年齢の変化。
- サイトの先頭に並ばなかった、新しい猫。

これらは、設定で保存したデータを削除すれば、全てのページを取得し直して、反映されます。自動で反映する方法は、`TODO.md` に残してあります。

## サイトに負荷をかけない

- 取得するのは、上の表のときだけです。決まった時間ごとの取得は、しません。
- ページは、1 ページずつ順に取得します。写真は、同時に 2 枚までです。
- 名乗る User-Agent (`gaia-neko/0.1 (+https://github.com/sluchin/gaia-neko)`) を付けます (`SiteFetch.kt`)。
- `robots.txt` は、全てを許可しています (2026-10-17 に確認)。

## 写真と文章の扱い

- サイトの写真と文章は、アプリにも、リポジトリにも、含めません。実行のときに、サイトから取得します。
- テストの HTML は、サイトと同じ作りの、ダミーです (実在の猫の名前や写真を書きません)。
- 開発者は、ニャン友ねっとわーく北海道の関係者で、アプリで一覧と写真を表示することに、問題はありません (2026-10-17 に確認)。写真の権利は、ニャン友ねっとわーく北海道にあります。
